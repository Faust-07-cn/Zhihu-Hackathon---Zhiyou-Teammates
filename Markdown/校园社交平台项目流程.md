# 校园社交平台 — 黑客松项目流程

> 配套文档：[需求文档](./校园社交平台需求文档.md)
> 赛事：知乎黑客松（允许调用 AI 工具）
> 日期：2026-09-12
> 分工：浮士德（前端 JS/HTML/CSS + 后端 Python）、团队协作（测试与评审）

---

## 1. 项目定位与目标
- 一句话描述：面向校园场景的高粘性社交平台，核心为**搭子匹配**与**校园讨论区**。
- 差异化切入点：用**标签+问卷协同匹配**满足"竞赛/项目组队"这一未被满足的刚需。
- 黑客松策略：聚焦一个 MVP 亮点（搭子匹配）+ 一个内容模块（讨论区），把"可信度体系"作为展示性亮点。

## 2. 里程碑总览

| 阶段 | 内容 | 里程碑 / 可演示产物 |

## 3. 技术方案

| 层 | 选型 | 说明 |
|----|------|------|
| 前端 | JavaScript + HTML/CSS（原生或轻量框架） | 浮士德负责，降低部署复杂度 |
| 后端 | Python（Flask/FastAPI） | 提供 REST API 与匹配逻辑 |
| 数据 | 轻量（SQLite / JSON / 内存库） | MVP 阶段避免重依赖 |
| 测试 | 局域网双机模拟通信 | 验证真实网络下的匹配与联调 |

**网络拓扑（MVP）**：客户端 A、客户端 B 通过局域网连接后端服务，可模拟"两人匹配 → 组队 → 交流"闭环，作为黑客松现场演示。

## 4. 分阶段开发流程

### 阶段 1：MVP（P0）
目标：跑通**兴趣搭子**的最短链路。

- [ ] 1.1 搭建后端服务框架（Flask 路由 + 数据模型）
- [ ] 1.2 设计标签数据结构（学习/兴趣/课程等字段）
- [ ] 1.3 实现标签匹配算法（交集 / 相似度打分）
- [ ] 1.4 搭建前端基础框架（页面骨架 + 路由）
- [ ] 1.5 实现前端：注册/登录、编辑标签、匹配结果页
- [ ] 1.6 前后端联调，局域网双机验证
- **验收**：两个账号提交标签后，能相互匹配并展示匹配结果。

### 阶段 2：二期（P1）
目标：支持**项目搭子（竞赛等）**的高门槛匹配。

- [ ] 2.1 问卷编辑器（后端数据结构 + 前端配置页面）
- [ ] 2.2 预设竞赛组队问卷模板（爬虫题库或手工构造）
- [ ] 2.3 问卷筛选 & 匹配逻辑（标签 + 问卷答案加权）
- [ ] 2.4 前端：问卷填写页 + 高门槛匹配流程
- **验收**：发布项目组队需求 → 填写问卷 → 过滤出符合条件队友。

### 阶段 3：讨论区（P2）
目标：提供 UGC 内容与平台粘性。

- [ ] 3.1 讨论区数据结构（帖子/回复/分类）
- [ ] 3.2 内容分层：默认展示学习/竞赛话题，娱乐需主动探索
- [ ] 3.3 讨论区热度排序算法（时间衰减 + 点赞/回复权重）
- [ ] 3.4 前端：讨论区列表页、发帖、详情、回复
- **验收**：可发帖、浏览、按热度排序。

### 阶段 4：可信度体系
目标：增强搭档信任度，降低协作成本。

- [ ] 4.1 定义 LV 等级 / 芝麻信用式评分规则（见待确认问题）
- [ ] 4.2 后端评分计算（完成度、协作评价、活跃度）
- [ ] 4.3 前端：用户主页展示等级 / 评分
- **验收**：用户主页可见可信度信息，可根据它辅助决策。

### 阶段 5：收尾
- [ ] 5.1 全流程联调（注册→匹配→组队→讨论→信任）
- [ ] 5.2 双机演示脚本 + 录屏
- [ ] 5.3 打包 / 部署说明
- [ ] 5.4 撰写答辩材料（痛点、方案、AI 使用、成果）

## 5. AI 工具应用策略（强调黑客松加分点）

利用 AI 提升开发效率与内容质量，并在答辩中体现"AI 赋能开发"：

1. **AI 辅助编码**：用 AI 生成前端组件、后端 API 骨架、匹配算法初版，浮士德负责审查与集成。
2. **AI 构建题库/内容**：用 AI 生成竞赛组队问卷模板、种子讨论帖（覆盖课程评价、生活资讯），快速填充 MVP 内容。
3. **AI 生成匹配规则**：让 AI 协助设计标签权重与问卷打分策略，人工校准边界情况。
4. **AI 演示支持**：用 AI 编写双机演示脚本与对话台词，便于现场讲解。
5. **AI 答辩辅助**：用 AI 整理产品亮点与数据讲故事，突出差异化（竞赛组队刚需 + 可信度）。

> 提示：答辩时明确列出"哪些环节由 AI 完成、哪些由人工把关"，体现可控与可信。

## 6. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 局域网网络不稳定 | 双机演示失败 | 预置本地回环降级模式 |
| 匹配算法过于简单 | 缺乏说服力 | 提前准备 1-2 组对比数据演示 |
| 讨论区内容审核 | 违反平台规范 | MVP 仅演示，审核机制列入待确认项 |
| AI 生成代码质量问题 | 集成出错 | 关键逻辑人工审查 + 单测 |
